# 迷你示例项目

这是 story-flow 设计阶段真实试跑（2026-07-11）留下的完整产物，展示**一章走完全流程**后每个文件长什么样：

- `docs/创意brief.md` —— 输入：用户的一句话需求
- `设定/` + `大纲/` —— 初始化产物（真实项目此层由 story-long-write Phase 1-3 生成，此处为压缩版）
- `大纲/章节清单_第1卷.md` —— 带勾选的进度账本，C-0001 已闭环
- `设定/门禁配置.json` —— 全书级门禁阈值（占比/容差）；单章字数区间在控制卡上
- `控制卡/C-0001.md` —— 动笔前的单章规格（注意"禁止事项"栏）
- `正文/C-0001-被诬偷玉.md` —— 经 5 轮门禁后的成稿。用当前脚本可复现：`check_gate.py 正文/... --config 设定/门禁配置.json --min-chars 2400 --max-chars 2640` → 2579 字（全码点口径，中文字符 2028）✅、对话 23.8%（容差带内）✅、linter blocking 清零
- `追踪/上下文.md` / `追踪/伏笔.md` —— 回写产物；注意 F002 的"记实际不记计划"偏差标注
- `追踪/METRICS.md` —— 5 轮门禁的完整失败明细与教训，正是 gate-policy 容差/预算规则的实证来源
- `.flow-status.json` —— 状态落盘格式

试跑时尚未实现 beat 预算与写手预检（它们正是从这 5 轮教训中来的），所以真实运行的预期轮次应显著低于本示例——见 references/architecture.md 试点验收指标。
