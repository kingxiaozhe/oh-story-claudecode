# story-flow 设计决策记录（ADR）

> 本文档记录 v1 的来源谱系、关键决策与冻结范围。改动流程机制前先读这里，避免重新发明或推翻有实证依据的决策。

## 来源谱系

设计吸收自七个体系的交叉验证：cm-workflow（软件开发流水线：N1-N8 状态机、specs 三件套、agent 管纪律/skill 管技术、状态落盘）、Novel Control Station（文档真值层、章节控制卡、线索热度、去AI味三步序）、novel-creator-skill（机读门禁产物、反向刹车概念、编排卫生；反面教训：关键词伪检查、文档超前于实现）、wangwen/fanqie-novelist（六件套真值、状态回写铁律、伏笔超期警报、七维 linter）、chinese-novelist-skill（JSON 状态机、校验-重写闭环）、以及本仓库既有的 story-* 体系（真值层与写作方法的实际承载者）。

## 关键决策

1. **管控层，不是写作层**。story-flow 不含任何写作技法；写作方法 100% 复用 story-long-write。避免两套方法论漂移（check-shared-files.sh 式的一致性负担）。
2. **复用既有真值层**。`追踪/伏笔.md`（未埋/已埋/已回收/已过期）、`追踪/上下文.md`、`追踪/角色状态.md`、细纲协议、大纲五检均直接使用，story-flow 只新增管控物（控制卡/清单/METRICS/门禁产物/状态 JSON）。
3. **每章新鲜写手子代理，替代 /clear**。skill 无法给自己清上下文；子代理天然实现"新鲜大脑 + 完整规格"，同时把写手与审查分离，消除自审盲区。solo 降级沿用仓库惯例。
4. **门禁分三级 + 容差带**。blocking（必修）/ advisory（留痕放行）/ 预算类（字数、占比，带容差）。实测依据：linter 默认 fail-on=all 会让每章必回炉（破折号零容忍）；1899/1900 差 1 字判死无意义。容差数值以 gate-policy.md 与 `设定/门禁配置.json` 为准，本文不重复。
5. **回炉轮次按检查类型分类**——对 cm"两轮上限"的修正。预算类修复是收敛的（给精确数字），不限轮；语义 blocking 两轮上限后分流（一致性/安全→人工，风格→留痕放行）。实测依据：试跑 5 轮中 3 轮是预算类，若受两轮上限会错误分流。
6. **欠字在细纲层根治**。初稿字数实测低估约 40%（1323/2200，CJK 口径试跑值，其中部分是口径差放大）。字数预算直接采用 `skills/story-long-write/references/artifact-protocols.md` 情节点序列的 Σ预算契约：区间 [章目标, 章目标×1.1]（章级余量，**不是**逐点超写），写手提交前必须自跑预检。全流程字数口径统一为全码点 `len(text)`（见 gate-policy.md），与细纲预算、check-prose hook 同源。
7. **deslop 终检独立成轮**。扩写会引入新机械指纹（实测：扩写轮新增 9 处微动作复读）。所有内容修复完成后才跑最后一次风格检查。
8. **git 当手改传感器**。每章全绿后 commit（若项目是 git 仓库）；N1 用 diff 检测人工改稿，触发增量回写而不是让状态静默腐烂。非 git 项目降级为 mtime 对比 + 建议 git init。
9. **冷读审查补"读者视角"**。形式门禁全绿≠好看。冷读代理只读正文回答追读三问，结论与控制卡承诺对账。每章轻量版，N6 阶段深版。
10. **状态落盘协议与 cm-workflow 兼容**。`.flow-status.json` 字段对齐，cm 的状态条/看板/像素流水线可直接复用于写作进度。

## v1 冻结范围

**做**：初始化/变更模式、N1-N8 状态机、控制卡、check_gate.py（字数/对话占比/容差/修复预算/配置文件）、`设定/门禁配置.json` 配置层、门禁分级与轮次规则、冷读轻量版 + N6 对接 /story-review 深审、九项回写落账、METRICS（含 waive 计数）、git 手改检测、任务清单镜像、OpenCode command 模板（CI 强制的集成必需项）、示例项目。

**明确不做（防 novel-creator 式膨胀）**：RAG/故事图谱、双模型交叉审查（留接口：N4 产物格式已兼容外部复审报告）、story-setup 的 Codex agents/hooks 适配扩展、平台运营层（标题去重/审核红线扫描/存稿节奏）、可视化面板移植、短篇流水线。以上任何一项，须先拿到试点 METRICS 数据再立项。

## 试点验收指标（达标才算 v1 交付）

用示例项目或真实项目连跑 ≥5 章，以 METRICS 为准：

- 每章回炉轮次中位数 ≤ 2（试跑基线：5 轮，改进来自 beat 预算 + 写手预检）
- 首稿欠字率 < 20%（基线：欠字 40%）
- 人工介入 ≤ 1 次/章（业务确认除外）
- 门禁分流到人工的比例 < 10%
- 冷读追读意愿平均 ≥ 3.5/5

## 实测数据附录

**设计期试跑（2026-07-11，无写手子代理/旧 CJK 口径/逐 beat 超写，作为基线）**：1 章 = 1 初稿 + 4 轮修复。R1：风格 blocking×8 + 欠字 577；R2：欠字 61 + 对话占比 -4pt（扩叙述压低占比）；R3：差 1 字 + 对话 -3pt + 新增微动作复读 9 处；R4：对话 -1pt；R5（精确预算修复 26 字对话）：全绿。完整产物见 examples/迷你示例项目/。

**v0.1 试点（2026-07-11，完整流水线连跑 C-0002~C-0005 共 4 章）**：验收结果——回炉轮次中位数 **1**（1/1/1/2，目标 ≤2 ✅）；N4 入口欠字率 **0%**（首稿欠字 2 章均在写手预检消灭，幅度 17.3%/3.2%，对比基线 40%）；人工介入 **0**（✅）；分流人工 **0%**（✅）；冷读追读均分 **4.0/5**（✅）；风格 blocking 4 章合计 **0** 处（基线单章 8 处）。总轮次较基线下降 75%，来源=细纲 beat 预算 + 写手预检 + 文风约束前置。过程验证：写手纪律协议 4/4 合规并上报 2 个真实正典问题；N6 反馈回路完整闭环（"过程段偏慢"三连击 → 修正指令注入 → advisory 消失）；连读深审期待零偏移、悬念 6/6 在账并反向补账 1 条。
**v0.2（已实施，2026-07-11）**：①验收指标「首稿欠字率<20%」改为「N4 入口欠字率<5%」；②N3 卡派生五检；③破坏性测试通过（手改检测/幽灵章节/打勾前中断三场景全部被 N1 逻辑捕获）；④语义对卡审查子代理化（调度员上下文不随章数膨胀）；⑤写手派发指令模板化；⑥METRICS 增成本列；⑦N5 热度扫描（吸收 NCS 线索热度，角色 3-5 章无有意义触碰报警，禁走过场）；⑧check_gate 文风指纹（句均长/单句段占比，N6 漂移对比）；⑨N6 修正指令自演化纪律（≥2 次才固化、每批 ≤3 条、连续 2 批无触发即撤销，吸收 wangwen 协议）；⑩作者侧三件套：批次验收包（N8）、作者巡检点（author_checkpoint_every）、冷读抽检开关（cold_read_mode）。

**观察名单（出信号才做）**：速记双清单（速记漏项导致写错时）、章型门禁预设（某章因章型被占比门禁误杀时）、对标接入（真实带拆文资产的项目跑批时）、可视化移植（无人值守长批量需求出现时）、双模型复审（门禁全绿但人工抽查发现质量问题时）。
