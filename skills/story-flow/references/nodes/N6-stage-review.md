# N6 阶段审查

**触发表**（满足任一）：每 5 章；卷末；高危章完成后（主线级伏笔回收章、主要人物首登场/退场章、卷内高潮章）；METRICS waive 列近 5 章同维度 ≥3 次；连续 2 章冷读 <3。未触发时本节点直接跳过。

**审查主体：调用现有 `/story-review`，不自建审稿逻辑**（它已有 4-Agent 多视角、统一 Findings Schema、跨批连续性继承与 solo 降级）：

1. **每 5 章触发** → `/story-review lean`（结构 + 设定一致性）；**卷末触发** → `/story-review full`（含文字自然度维度）。审查范围=近批章节。
2. **story-flow 补充项**（story-review 不掌握流水线上下文，由调度员补做）：
   - 冷读深版（cold-read-review.md：节奏重复感、期待偏移、弃书点）；
   - 节奏对账：近 5 章实际张弛 vs 卷纲章节定位标注；
   - METRICS 回看：waive 分布、冷读分数曲线、轮次趋势。
3. **产出** `追踪/阶段审查_第{X}批.md`：story-review 报告（按其 Schema）+ 补充项结论，收敛为三档——
   - 无系统性问题 → 留档继续；
   - 模式性问题（如连续章开场同构、同维度 waive 聚集）→ 生成修正指令注入后续批次控制卡的「禁止事项」栏。**固化纪律（v0.2，吸收 wangwen 自演化协议）**：同类问题出现 ≥2 次才允许固化为修正指令（单次先记观察）；每批注入指令 ≤3 条防堆积；某指令连续 2 批未再触发对应问题 → 撤销该指令并在阶段审查留痕——规则只增不减就是管控层自己在注水；
   - 卷级问题（期待偏移、节奏结构性失衡）→ 暂停出决策卡（调卷纲走变更模式 / 接受并记录）。
4. story-review 不可用（skill 未部署等）时按其自身降级链走 solo，报告标注 fallback；不得因此跳过阶段审查。
5. 写 `.flow-status.json`（node:N6）。
