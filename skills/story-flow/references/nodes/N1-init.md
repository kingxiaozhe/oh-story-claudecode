# N1 初始化与断点恢复

1. **解析输入**：项目目录、本次目标（写到第几章 / 批量 N 章 / 写完本卷）。未指明批量数默认一批 3 章。
2. **三方交叉核对**（断点恢复的核心，不是可选项）：
   - `大纲/章节清单_第X卷.md` 的最后一个 `[x]`
   - `追踪/上下文.md` 的最新章节记录
   - `追踪/METRICS.md` 的最后一行
   - `正文/` 目录的实际文件
   四者一致 → 从下一章继续。**首次运行的空态（清单无任何 [x]、上下文仅初始态、METRICS 只有表头、正文/ 为空）视为一致**，从清单第一个未勾章开始。不一致 → **停止并逐项列出差异**，最常见原因是上次回写中断：正文存在但未打勾 → 补走 N4-N5（不重写）；打了勾但追踪缺记录 → 补回写。修复完成后重新核对，一致才继续。
3. **手改检测**：
   - git 项目：找最近一次 `story-flow:` 前缀 commit，`git diff` 其后的 `正文/`、`设定/`、`大纲/` 改动。有正文手改 → 对改动章执行**增量回写**（重读该章，更新 追踪/上下文·角色状态·伏笔 中受影响条目，METRICS 备注"手改回写"）；有设定/大纲手改 → 提示可能需要变更模式。
   - 非 git：对比 `正文/*.md` mtime 与 `.flow-status.json` 的 `at`（完整日期时间，格式见 SKILL.md），晚于者视为疑似手改，提示用户确认（精度有限，如实说明）。
4. **加载上下文（预算硬上限）**：默认只读卷纲 + 章节清单 + `追踪/上下文.md` 最新两节。设定/伏笔/角色详情留给 N3 按"本节速记"协议（story-long-write state-tracking.md）按需筛取，不全量加载。
5. 写 `.flow-status.json`（node:N1，detail 大白话，如"从第 13 章继续，检测到第 7 章有手改已补账"）。
