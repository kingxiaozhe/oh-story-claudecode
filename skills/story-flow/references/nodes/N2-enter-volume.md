# N2 进卷与批次计划

1. **读卷纲 + 清单**，确定本批章节（严格串行，章与章之间禁止并行——第 N 章是第 N+1 章的输入）。
2. **细纲与 beat 预算强制补齐**：本批内任何一章缺 `大纲/细纲_第XXX章.md` 或细纲无 beat 字数预算 → 现在按 story-long-write Phase 3 细纲协议补齐并落盘，不允许"边写边补"。beat 预算之和即控制卡字数预算的来源。
3. **伏笔前瞻**：查 `追踪/伏笔.md`，列出本批到期/临期的回收与呼应义务，映射到清单对应章；发现"计划回收章不在本批且已超期" → 按 gate-policy 分流规则出决策卡（顺延并改账 / 插入补救章）。
4. **任务清单镜像**：本批章节 TaskCreate 一章一条（含章号与章名）；断点恢复时已 `[x]` 章跳过，不重复创建。
5. **批次计划汇报**（一次性，之后批内不再询问）：本批章列表、每章定位与伏笔操作、预计字数。无人值守模式下此汇报只落盘不等待确认。
6. 写 `.flow-status.json`（node:N2）。
