# N3 写章

0. **声口硬闸（铁律 8，先于一切）**：检查 `设定/声口.md` 存在且含实质内容（含 §采纳区+配额/§禁用区/§语气词库，参 声口库/_模板.md）。**缺失则本章及后续所有章一律不写**——`.flow-status.json` 置 `paused_for_human`（detail："缺声口文件，等作者定嗓音"），引导作者走 声口库/README.md「来源仪式」：推荐 1-3 本同频道同赛道参考书 → 作者选定母本 → 炼制 → 绑定（**新书旧书同流程**，旧稿原文只作分寸校准不作主来源），文件头绑定登记齐全且**作者读过认可后**才恢复流水线。
1. **生成控制卡**：按 [../templates/控制卡.md.tmpl](../templates/控制卡.md.tmpl) 从「细纲 + 卷纲定位 + 追踪状态」派生，落盘 `控制卡/{章号}.md`。低压/关系章必须走"低压合法路径"，禁止硬塞爽点（对齐 story-long-write 章节定位与张弛）。
   **卡派生五检**（v0.2 新增，逐项对细纲核对后卡才生效）：①视角——细纲有无切镜/多视角段，例外写进卡；②出场白名单——细纲每个情节点的在场人物都在名单上；③债务——上章"下章承接压力【必须】"项全部进"回收债务"栏；④禁令——不揭底事项与后续章节的揭示计划无冲突；⑤预算——区间=[细纲目标, 目标×1.1] 且细纲有"预算合计"行。
2. **准备本节速记**：按 story-long-write `references/state-tracking.md` 协议，从追踪与设定中筛出"不知道就会写错"的最小集。
3. **派发写手子代理**（narrative-writer 优先，按仓库降级惯例找不到则 solo）。派发词按 [../templates/派发指令.md.tmpl](../templates/派发指令.md.tmpl) 填变量生成，固定段落（文风基线/预检/纪律/汇报格式）禁止临场改写。写手输入 = 控制卡 + 本节速记 + 细纲 + 文风基线 + 上一章末尾 500 字。**不给全量设定**。
4. **写手纪律**（写入派发指令）：
   - **写作程序=段落级声口优化循环，唯一且无例外**（v0.2.3 废整章写法；v0.2.4 声口硬闸）：写一段→只按 `设定/声口.md` 优化一段→防雪球自检→下一段。程序细则由派发模板固定段落承载；
   - 只写本章正文，按细纲情节点序列逐点完成，**全章落在控制卡字数区间 [细纲目标, 目标×1.1] 内**（Σ预算契约见 story-long-write artifact-protocols.md，不做逐点超写）；
   - 不改控制卡/清单/追踪/设定的任何文件，发现设定矛盾写入汇报不自行修正；
   - **提交前预检**：自跑 check_gate.py（路径探测与解释器探测惯例见 gate-policy.md「工具路径与调用」；字数区间出自控制卡，占比/容差出自 `设定/门禁配置.json`）与 story-deslop linter `--fail-on=blocking`，未过自修最多 1 轮再交稿；
   - 汇报固定格式：正文落盘路径、预检结果（含自修说明）、实际埋设的伏笔与计划的偏差、对细纲的偏离及理由。
5. 正文落盘 `正文/{章号}-{章名}.md`。写 `.flow-status.json`（node:N3，detail 如"正在写第 14 章：当铺对峙"）。
