# N5 回写落账

门禁全绿后执行；**全部完成才算本章闭环**，中断即留下 N1 三方核对能发现的痕迹。

1. **追踪回写**（按 story-long-write artifact-protocols.md 既有格式）：
   - `追踪/上下文.md`：本章摘要、状态变化、未兑现承诺、下章承接压力（分必须/可选两档）
   - `追踪/角色状态.md`：出场角色状态与关系变化（写"从…→…"）
   - `追踪/伏笔.md`：本章埋/推进/回收的伏笔状态流转；**记实际不记计划**——提前埋、漏埋、顺手埋了计划外的，都如实改账并在备注标注偏差
   - `追踪/时间线.md`：如有时间跨度
2. **每 5 章双扫描**：
   - 伏笔超期扫描：过期伏笔列表 → 轻则记 METRICS 备注，重（主线级）则决策卡；
   - **热度扫描**（v0.2，吸收 Novel Control Station 线索热度）：从 `追踪/上下文.md` 近 5 章条目统计每个核心角色/支线的**有意义触碰**（推进/改变期待/转移压力才算，露脸不算）。核心角色 3-5 章、支线 4-6 章无触碰 → 热度降为 cold 并报警，写入下一批批次计划；响应只允许五种（直接推进/间接提醒/压力转移/合理休眠标注/有意归档），**禁止走过场客串**。
3. **清单打勾**：`- [x] {章号} …｜实际{字数}字·{轮}轮`。
4. **METRICS 落行**：轮次、失败明细（压缩成一行）、最终字数（全码点口径，取门禁产物的 total_chars）、人工介入、waive（`w:{维度}`，无则留空）、**成本（写手 tokens 约数 + 耗时，可得则记，不可得记 `-`）**、备注（含冷读对账偏差、指纹漂移异常）。
5. **git commit**（若项目为 git 仓库）：`story-flow: {章号} {章名} ({轮}轮)`，范围含正文/控制卡/追踪/清单/门禁产物。这是 N1 手改检测的锚点。
6. TaskUpdate 该章 completed；写 `.flow-status.json`（node:N5）。
