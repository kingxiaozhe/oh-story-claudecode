# chapter-qc-playbook.md：逐章生产闭环 · 质检改写套路

> 本文件是 `workflow-daily.md` Step 2/Step 3「确定性收尾」的实战强化版。
> 它把日更连写中**每章都会重复踩的坑与固定改法**沉淀成可照做的清单，
> 配套一键脚本 `scripts/qc-chapter.sh`。目的：把逐章 write→QC→fix→track→commit
> 变成机械可复现的闭环，不靠临场记忆。

---

## 一、每章闭环七步（照做）

1. **建/读细纲** `大纲/细纲_第N章.md`（缺则按 SKILL.md Phase 3 模板补建，不跳过）
2. **写正文** `正文/第N章_标题.md`（按细纲情绪/节奏/章型；相邻章章型不同构）
3. **一键质检**：`bash skills/story-long-write/scripts/qc-chapter.sh 正文/第N章_*.md`
4. **按 FAIL 逐条改写**（见下「二、blocking 改写套路」），改完**重跑脚本**直至全 PASS
5. **补足字数**：低于 90% 放行线时，补**实义内容**（对话/心理描写/闪回对照/具体把柄物），不注水；落在 [目标, 目标×1.1]
6. **更新追踪四件套**：`追踪/伏笔.md`（新增/回收，编号 F##）、`追踪/时间线.md`（本章事件行）、`追踪/角色状态.md`（有状态变化才改）、`追踪/上下文.md`（进度元信息）
7. **提交推送**（见「五、提交规约」）

> 连写时：一章 PASS + 追踪更新 + 提交后，直接进下一章，不逐章问「是否继续」（除非用户要求）。

## 二、blocking 改写套路（每章高频，机械照改）

### 1. 破折号 `——`（em-dash，blocking）
- **现象**：ai-patterns 报 `em-dash`。几乎每章都有。
- **处理**：`qc-chapter.sh` 已把 `normalize-punctuation.js` 排在最前，**破折号会被就地自动改成逗号/句号**，多数无需手动。
- **仅当**自动改后读感变差（如「打断对话」「拖长音」被压成生硬逗号）才手动按功能重写：打断→动作 beat 或短句；拖长音→省略或动作；插入说明→逗号/冒号。**勿一律改句号。**

### 2. 「不是X，是Y」/「不是X，不是Y，而是Z」（not-is-comparison，blocking）
- **现象**：ai-patterns 报 `not-is-comparison`。normalize 脚本**不会**自动修，必须手改。
- **改法**：删掉否定铺垫，直接写后项；或改成动作/细节呈现；或换非对比句式。
  - `记的不是收梢，是源头` → `记的是源头`
  - `不是巧合，是墓碑` → `哪里是什么巧合。那是一座墓碑。`
  - `用的不是"东家"，不是"大人"，而是…` → `既没称"东家"，也没叫"大人"，用的是…`
  - 注意：`不是…就是…`（二选一）不算命中；`哪里是A。是B。`（句号分隔+反问）通常安全。
- **自查**：补字数/改写时**最容易新引入** not-is，改完务必重跑脚本。

### 3. 软禁词（一级禁用，出现即替换）
- 高频误用：`缓缓`(→慢慢/一寸寸)、`仿佛/犹如/宛若`(→像是/删)、`眼中闪过`(→眼底透出/垂下眼)、`嘴角勾起`(→嘴角一扯)、`深吸一口气`(→顿了顿)、`不禁`、`，带着…`(拆短句/换动作，如「他领着人走」而非「他，带着人，走」——注意「，带着」会被扫描命中)。
- 完整表见 `banned-words.md`。

## 三、扩展扫描（`banned-words`/`元信息`之外，本闭环额外必查）

`qc-chapter.sh` 已内置，这里说明为什么加：

| 类别 | 正则 | 为什么查 |
|------|------|---------|
| 软禁词 | `缓缓\|仿佛\|眼中闪过\|，带着…` | 一级 AI 味词 |
| 元信息/工程词 | `上一章\|本章\|前文\|后文\|伏笔\|细纲\|读者` | 写作元信息不得进正文（ai-patterns 亦查） |
| **卷号泄漏** | `卷一\|卷二\|卷三…` | 写多卷时最易把「卷一里…」写进正文，属工程词泄漏（应改成世界内表达，如「当初查那桩旧案时…」）|
| **英文字母** | `[A-Za-z]` | 连写时手误把英文词混进中文正文（如把 two/neither/knowledge 之类误敲进句子：`这two件事`、`天大的knowledge`）。中文网文正文不该出现拉丁字母 |
| F编号 | `F[0-9]` | 追踪用的伏笔编号（F45/F55…）绝不能漏进正文 |

> 例外：标题行（第1行）不扫；若故事世界内角色真的在读「第X章」文本或真身为作者/读者，另行豁免。

## 四、字数纪律

- 目标区间 **[目标, 目标×1.1]**；**90% 为放行下限，非目标**。默认目标 2200 → 放行线 1980、上限 2420。
- 低于放行线：定位「欠账密点」，补**实义内容**——对话、心理描写、闪回对照、具体到可指认的细节（谁/什么物件/哪一处证据）；**不注水、不挤牙膏反复回炉**，一次补到配额。
- 高于上限：压过场、合并疏点收敛。
- 统计口径：**Python 字符数** `len(Path(f).read_text('utf-8'))`；不用 `wc -c`（按字节，中文偏大）。

## 五、执行顺序的坑（务必记住）

1. **normalize 必须在 ai-patterns 之前**跑（本脚本已排好）：normalize 就地清破折号后，ai-patterns 报的才是真正要手改的 blocking（主要是 not-is），一遍到位；否则每章都要「跑→改破折号→再跑」两趟。
2. normalize 会把 `……` 省略号一并归一/压平——若某处刻意的停顿被压没了，手动用短句/动作 beat 复原（别改回 `……`，硬门禁不让位）。
3. **每次补字数/改写后都要重跑脚本**：改写极易新引入 not-is 或英文手误。
4. **重复行自查**：插入段落时易造成重复（如同一动作句重复两次、同一句情绪 beat 连出两次）。改完通读衔接处一眼。

## 六、提交规约（每章一提交）

```bash
git add -A
git commit -q -m "第N章《标题》：一句话主线 + 本章质检状态

- 正文第0NN章 XXXX字，ai-patterns/degeneration/punct/禁用词/工程词/英文 零命中；章型X
- 本章伏笔动作（新埋F##/回收F##）
- 追踪四件套同步至第N章末

Co-Authored-By: <署名> <noreply@anthropic.com>
Claude-Session: <会话链接>"
# 推送带指数退避重试（网络失败才重试）
for i in 1 2 3 4; do
  git push -u origin <分支> && break
  echo "push failed, retry $i"; sleep $((2**i))
done
```

- 一章一提交，commit 正文写明字数 + 质检零命中 + 章型 + 伏笔动作，便于回溯。
- 只在用户要求时开 PR；分支按项目约定。

## 七、声口（文风）从哪来 —— 别只跑质检，先定嗓音

- 质检只保证「不出 AI 味、不违规、字数够」，**保证不了每章嗓音一致**。声口的权威来源是本书的 `设定/文风.md`（story-long-write「自定义文风模式」会读它作权威风格基：句长/标点节奏/对话潜台词/情绪交替以它为准）。
- **原创书（无对标）尤其要注意**：工作流对无对标项目默认跳过文风召回，**除非** `设定/文风.md` 存在且有实质内容（去空白 ≥200 字，且含 句长/标点/对话/锚点/笔调 小节 + 可执行约束）。因此原创书应在**前几章把声口定下来后，尽早蒸馏一份 `设定/文风.md`**——从已写章节里提炼句长带、标点节奏、对话方式、本书的标志手法、章首章尾习惯、用词质感与禁忌，并附 3–5 段原文锚点。此后每章续写自动按此嗓音生成，换会话也不走样。
- 一句话：**先有 `设定/文风.md`（写什么嗓音），再跑 `qc-chapter.sh`（把这嗓音稳定落盘留痕）——两者合起来才是完整的可复用写作闭环。**

## 八、与 workflow-daily.md 的关系

- 本文件**不替代** `workflow-daily.md`，是它 Step 2「写正文→字数验证→元信息扫描→禁用词扫描」与 Step 3「确定性收尾」的**可照做操作层**。
- 情绪/节奏/文风/对标召回、细纲蓝图消费、章型轮换等**创作层**决策仍以 `workflow-daily.md` + SKILL.md 为准。
- 一句话分工：**daily 决定「写什么、怎么写好」，本 playbook 决定「怎么把它稳定地跑过质检、落盘、留痕」。**
